## 0. The one design decision that had to be made first — login-activation threshold

The program plan and the task summary disagree on WHEN local login turns on:

| Source | Says |
|---|---|
| program plan §P9 line 283 | LoginGate "mounts ONLY when **>1** user exists" |
| program plan §P9 exit 289 | "**delete second user** → app returns to zero-login flow identical to today" |
| task opening (CRITICAL) | "with **0 or 1** user, the app behaves EXACTLY as today (zero-login)" |
| task item 8 (a TEST) | "**delete-second-user** → returns to zero-login solo mode identical to today" |
| task item 3 (prose) | "Login is REQUIRED only once **≥1** user exists" |
| task item 7 (prose) | "LoginGate mounts ONLY when **>0** users exist" |

The two **executable** exit-criteria (plan 289 + task item 8) both require: *2 users → login on; delete one → login off (zero-login)*. That is only true if login activates at **count ≥ 2**. Items 3/7's ">0/≥1" prose is the caveman summary being loose; the plan doc and the ground-truth test win.

**DECISION — `AUTH_ACTIVE_MIN_USERS = 2` (single named const, one-line flip if BOSS wants ≥1).**
`authActive() ⇔ users.count() >= 2`.
- **0 or 1 user → solo:** zero-login, token gate is the only auth, `decidedBy` defaults `"BOSS"` — byte-identical to today. (The "second seat" is literally the 2nd account; one account = still BOSS solo.)
- **≥2 users → auth active:** login required, session cookie enforced, roles enforced server-side, `decidedBy` = the session user.

Disclosed deviation: task items 3/7 prose read ">0/≥1". I follow the plan + the executable tests (≥2). Flip point: `AUTH_ACTIVE_MIN_USERS`. Tests cover the 0-user, 2-user, and delete-back-to-<2 transitions explicitly.

## 1. PRECONDITION-052.1 resolution (the in-phase BLOCKER) — model (a) single-tenant-all-see

ADR-052 says the SSE bus has NO per-client scoping: `events.emit()` writes every frame to every client and `Last-Event-ID` replays the whole `events_log` with no ownership predicate. Fine while single-principal + loopback; a BLOCKER the moment a second seat lands.

**Chosen resolution = ADR-052 option (a): single-tenant, all authenticated seats see the whole inbox** (task item 6: "one team, one inbox"). We do NOT add a per-user ownership column; instead we (1) DECLARE the trust model explicitly and (2) make the stream reachable **only by an authenticated principal**:

- The events-ticket mint (`POST /runtime/events/ticket`, already fully token-gated) gains an ADDITIONAL gate: **when `authActive`, it requires a valid session** (any role — a viewer legitimately watches the inbox). Solo → token-only exactly as today.
- Since the ticket is the only path to `GET /runtime/events`, and a ticket can now only be minted by a logged-in team member (or the solo token holder), an **unauthenticated** second party cannot open the stream at all → cannot receive user A's frames.
- Between authenticated team members, receiving each other's Delivery frames is **by design** (single-tenant), not a leak: they are one team sharing one inbox, same as they all see `GET /inbox`.

This flips PRECONDITION-052.1 → **RESOLVED** by *changing the trust model* (documented single-tenant) rather than by per-client scoping — which is the simpler and spec-endorsed of the two ADR-052 options. The authz-matrix proof required by the ADR becomes: *an unauthenticated caller (authActive, no session) cannot mint a ticket / open the stream (401)* — tested.

ADR-052 §"Preconditions" is amended in the same commit-set (PRECONDITION-052.1 → RESOLVED, with this rationale).

## 4. Security params (sr-security will hammer these)

- **scrypt**: `N=16384, r=8, p=1, keylen=64, saltlen=16` (random per user). Stored `scrypt$N$r$p$saltHex$hashHex`. Verify parses params, re-derives, `timingSafeEqual`. Unknown format → fail closed. maxmem sized for N (128·N·r = 16 MiB).
- **No enumeration**: login failure is one generic `401 {error:"invalid credentials"}` for BOTH unknown-user and wrong-password; unknown-user path still runs a scrypt against a dummy hash so timing does not disclose existence.
- **Cookie**: `HttpOnly; SameSite=Strict; Path=/; Secure` iff the request Host is NOT loopback (so it still sets over http on localhost). Host-only (no Domain). Opaque 32-byte session id; never contains the name/role.
- **Session**: in-memory Map, TTL (12h default), revoked on logout, swept lazily; restart drops all sessions (acceptable — solo is default, and no session secret persists at rest).
- **Roles server-side**: viewer → 403 on decide/assign/policy/adapters/workspace/config/users-write, proven by direct curl (not just hidden buttons). approver → allowed. Token gate stays underneath (defense in depth).
- **decidedBy** is the SESSION identity when authActive — never the client-supplied `by` (a viewer cannot forge an approver name; body `by` is ignored when authActive).

## 6. Known risks / deferred (labeled)
- Packaged-electron (cross-origin 127.0.0.1:3005) multi-user cookie flow not exercised — solo (the electron default) is unchanged; browser/dev multi-user is the P9 target. Labeled.
- Assignment does NOT emit a new SSE event (catalog is CLOSED + security-reviewed). Cross-seat assignment propagation is via the assigning client's optimistic update + other seats' next `/inbox` fetch (mount/resync). Advisory metadata — acceptable; widening a closed catalog is worse. Labeled.
- Sessions in-memory (not SQLite): restart logs everyone out. Chosen for security (no secret at rest); solo default means BOSS never notices. Labeled.
