# F4.1 — Packaged swarm-state data plane (port 5 vite-dev feeds) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Code steps RED→GREEN→commit. New HTTP write surface → security-reviewer BLOCKING before commit.

**Goal:** The packaged cockpit is stuck on "connecting to swarm…" because its 5 data feeds (`/api/state.json`, `/api/command`, `/api/audit`, `/api/commands/status`, `/api/sessions`) are vite **dev-only** middleware. Port them into the agent-runtime (already on :3005 with the base/token switch) so the packaged app renders the roster/board/chat. DRY: dev keeps the same behavior by reusing the SAME handler module.

**Architecture:** Extract the 5 handlers verbatim from `vite.config.ts` into a shared framework-agnostic ESM module `agent-runtime/cockpit-feeds.mjs` (handlers take `(req,res)` over a closed-over `statePath` — works under both vite connect-middleware and node:http). Mount them in `server.mjs` (loopback-gated by the existing `hostOk`, NO runtime token — matches dev's no-auth posture). Refactor `vite.config.ts` to import the same handlers. Client: prefix the 5 URLs with `runtimeUrl()` so dev→relative (vite), packaged→`127.0.0.1:3005`. Electron main passes `WAAHYU_STATE_PATH`.

**Tech Stack:** Node ESM, node:http, `node --test`.
