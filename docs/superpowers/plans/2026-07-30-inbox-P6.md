# P6 — Risk Router · Policy · SLA  (ADR-053)

Anti-approval-fatigue layer. Deliveries get auto-classified by risk; a BOSS-editable
per-band policy decides auto-approve (low) / human (med) / typed-confirm (high); SLA
timers escalate; everything is audited. This UNBLOCKS the `auto_approved` status that
P2/P4 deliberately reserved for this ADR.

Provenance read: program plan §2 + §P6, master-spec §4 (M4), SESSION_MEMORY P2–P5 exits,
and the live code (deliveries.mjs / policy.mjs / events.mjs / db.mjs / guards.mjs /
engine.mjs / server.mjs / the inbox UI). Caveman-terse.

## Architecture decision — auto-apply scope (a documented boundary)

There are **two orthogonal auto-apply axes**:
1. **ADR-029 per-agent** (`enginePolicy`) — the engine's autonomy-loop gate. Default OFF
   (level=manual ⇒ HELD). Applies into the worktree; never sets a delivery status.
2. **P6 per-band** (`bandPolicy`, this ADR) — the DELIVERY-level decision that sets
   `auto_approved`.

To avoid a double-apply race between the two gates (engine `runStep` runs its ADR-029
gate synchronously right after the synchronous `onDiffed` mint), P6 wires its band
auto-apply on the **manual mint path only** (`mintFromSandbox`/`mintManual` →
`maybeAutoApply`) — which is exactly the path provable on the mock backend (seed a
sandbox → `/changes` mints → policy auto-applies). **Engine-path band auto-apply is
DEFERRED/labeled** (needs the two gates unified; a follow-up). Engine deliveries STILL
get risk band + SLA at mint and route to a human — the conservative default the spec
wants (auto-approve OFF by default). Nothing regresses.

## Auto-apply safety (four independent gates, deny-by-default)

`maybeAutoApply` auto-approves a pending delivery only if ALL hold:
1. `bandPolicy.routeFor({band, changedPaths}) === 'auto_approve'` — deny-list is a HARD
   pre-filter inside `routeFor` (any deny glob ⇒ 'human', overrides band).
2. `band !== 'high'` (typed_confirm high can NEVER auto-apply).
3. **every** changed path `isAutoSafe(p)` (reused ADR-029 classifier ⇒ applyAllowed ∧
   ¬CONFIG_GUARD ∧ ¬exec).
4. `deliveries.autoApprove` then runs the **identical broker** `applyChanges` (applyAllowed
   + CONFIG_GUARD + symlink + containment) and marks `auto_approved` ONLY if the apply is
   fully clean; any refusal ⇒ stays pending for a human.

Tampered/absent policy ⇒ ALL-HUMAN (fail closed). Auto-applied rows STILL land in the
Inbox (collapsed Auto strip) with a `policy.autoapplied` event + `delivery.auto_approved`
audit line carrying the reasons.

## Risk classifier (`risk.mjs`, pure, table-driven, no LLM/network)

`classify({changedPaths, additions, deletions, kind, source})` → `{score 0..100, band, reasons}`.
- Path→band: HIGH = auth/secret/.env/payment/infra/ci/.github/Dockerfile/migrations;
  MED = src/**, services/**; LOW = tests/**, docs/**, *.md, changelog. Band = the
  MAX over all paths.
- Diff-size bump: a large diff bumps one band up past a threshold.
- New-dependency detector: added deps in package.json/pyproject/requirements/go.mod ⇒ ≥MED.
- `kind==='failure'` ⇒ its own band (HIGH — a stuck agent needs prompt attention).
- Deterministic; score is a monotone function of the reasons. ≥25 test cases.

## SLA

Per-band absolute-UTC deadline set at mint (`low 24h · med 8h · high 1h`, policy/env
overridable). `sweepSla(atMs)` (pure, in deliveries.mjs) drives once-only escalation via
`slaState`: →halflife (emit `delivery.sla_halflife`, re-notify once) →expired (emit
`delivery.expired`, escalate). **Expired pending deliveries are NOT auto-decided** — they
escalate only. A `setInterval` in server.mjs (unref'd, 60s) + one boot sweep drives it —
kept OUT of the dispatch scheduler (which by design owns no wall-clock timer). Countdown is
rendered CLIENT-side from the absolute deadline (no server tick drift).
