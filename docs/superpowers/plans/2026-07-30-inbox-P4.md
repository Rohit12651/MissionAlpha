# P4 — Autonomy: queue · retry · auto-chain · failure deliveries

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **COMMIT POLICY (program plan §4):** there is NO commit step in this plan. Every task ends with **Checkpoint:** `git add -A && git status` — review, leave staged.

**Goal:** BOSS queues N tasks and walks away — agents run in parallel (≤MAX_INFLIGHT, per-agent serial), fail, retry, self-heal, auto-chain on approval, survive `kill -9`, and surface as Deliveries (including *failure* Deliveries) so a stuck agent never dies silently.

**Architecture:** ADR-024/025/027/028 are ALREADY IMPLEMENTED (`engine.mjs`, `scheduler.mjs`, `queue.mjs`, `self-heal.mjs`). P4 does not rebuild them — it (a) closes four real behavioural gaps found by code audit, (b) wires the four `task.*` events that P2 declared but nothing emits, (c) adds the ADR-051 §9 failure-Delivery hook, (d) adds one Inbox surface (`QueueStrip`) fed by those events.

**Tech Stack:** Node 20 mjs · better-sqlite3 (WAL, append-only migration ladder) · SSE (`events.mjs`, closed 9-name catalog) · React 19 + TS strict · `node --test` (runtime) / `node --experimental-strip-types --test` (src/lib).

### 0.1 Deviations from the program-plan P4 "Files" line (declared, not silent)

1. **No new `POST /runtime/queue` / `GET /runtime/queue` routes.** `POST /runtime/engine/enqueue` and `GET /runtime/engine/runs` already provide exactly those semantics behind the same token+origin gate, with a `steps[]` goal model the engine needs. Adding a second pair would create a second auth surface and a second enqueue path for zero capability. **Decision: reuse.**
2. **Queue store stays file-backed, not SQLite.** The program-plan P4 line says "durable task table in SQLite". ADR-027 is explicit that the JSON record schema *is* the future DB row and that `queue.mjs` exposes a narrow interface precisely so the store can swap later without touching engine/scheduler. The file store already satisfies every P4 exit criterion (durable, crash-safe, atomic claim, restart-resume — proven by Task 8). Porting it to SQLite is a storage migration with zero behavioural delta and a real risk of regressing the proven atomic-claim path. **Decision: defer the store port; record as DEFERRED in the exit report.**
3. **No `task.done` event.** The event catalog is CLOSED and verbatim from program plan §2 (`events.mjs` comment). There is no success-terminal name, so `QueueStrip` learns about DONE/HELD/CANCELLED from a debounced authoritative snapshot re-read (§0.2), not from a delta. Adding `task.done` would be a wire-contract amendment and needs BOSS sign-off. **Decision: no new name; residual staleness documented.**

### 0.2 QueueStrip data flow (no polling)

```
mount / SSE resync ─────────────► GET /runtime/engine/runs   (authoritative snapshot)
task.queued|started|retried|failed ─► pure reducer  (instant delta, optimistic)
                                   └► 400ms trailing debounce ─► GET /runtime/engine/runs (re-truth)
delivery.created | delivery.decided ─► same debounced re-truth
```
No timer runs while the bus is quiet. The debounce is *trailing* so a burst of transitions costs one request, landing after the transitions settle.

```ts
// QueueStrip model (P4). PURE — zero DOM, zero network, so `node --test` imports it
// directly. The strip is push-driven off the four task.* names in the closed v1
// catalog (program plan §2); a periodic authoritative snapshot replaces state
// wholesale because the catalog has NO success-terminal event (a DONE/HELD task
// leaves the queue silently).
import type { RuntimeEvent } from "./useRuntimeEvents.ts";

/** The four buckets the strip renders. `failed` is terminal-and-visible. */
export type QueueBucket = "queued" | "running" | "retrying" | "failed";

export interface QueueTask {
  agentId: string;
  bucket: QueueBucket;
  /** Classified error kind on a failure (self-heal.mjs), else null. */
  kind: string | null;
}

/** Keyed by taskId so a replayed event can never double-count. */
export interface QueueState {
  tasks: Readonly<Record<string, QueueTask>>;
}

export interface QueueCounts {
  queued: number;
  running: number;
  retrying: number;
  failed: number;
  total: number;
}

export interface AgentChip {
  agentId: string;
  queued: number;
  running: number;
  retrying: number;
  failed: number;
  total: number;
}

export const EMPTY_QUEUE: QueueState = Object.freeze({ tasks: Object.freeze({}) });

/** Max chips rendered before the strip collapses to "+N more". */
export const MAX_AGENT_CHIPS = 6;

const EVENT_BUCKET: Record<string, QueueBucket> = {
  "task.queued": "queued",
  "task.started": "running",
  "task.retried": "retrying",
  "task.failed": "failed",
};

const str = (v: unknown): string => (typeof v === "string" ? v : "");

/**
 * Fold one catalog event into the state. Non-task events and events without a
 * taskId return the SAME reference, so React skips the re-render entirely.
 */
export function applyQueueEvent(state: QueueState, e: RuntimeEvent): QueueState {
  const bucket = EVENT_BUCKET[e.name];
  if (!bucket) return state;
  const taskId = str(e.data.taskId);
  if (!taskId) return state;
  const agentId = str(e.data.agentId) || "unknown";
  const kind = bucket === "failed" ? str(e.data.kind) || "unknown" : null;
  const prev = state.tasks[taskId];
  if (prev && prev.bucket === bucket && prev.agentId === agentId && prev.kind === kind) return state;
  return { tasks: { ...state.tasks, [taskId]: { agentId, bucket, kind } } };
}

/** One row of GET /runtime/engine/runs. */
export interface QueueSnapshotTask {
  taskId: string;
  agentId: string;
  status: string;
  attempts?: number;
  error?: { kind?: string } | null;
}

/**
 * Authoritative replacement. `queued` with attempts>0 is a task awaiting its
 * backoff, which the strip shows as `retrying`. Settled statuses (done / held /
 * cancelled) are simply absent — they have left the queue.
 */
export function fromSnapshot(tasks: readonly QueueSnapshotTask[]): QueueState {
  const out: Record<string, QueueTask> = {};
  for (const t of tasks || []) {
    const taskId = str(t?.taskId);
    if (!taskId) continue;
    const agentId = str(t?.agentId) || "unknown";
    let bucket: QueueBucket | null = null;
    if (t.status === "queued") bucket = (t.attempts ?? 0) > 0 ? "retrying" : "queued";
    else if (t.status === "claimed") bucket = "running";
    else if (t.status === "failed") bucket = "failed";
    if (!bucket) continue;
    out[taskId] = { agentId, bucket, kind: bucket === "failed" ? str(t.error?.kind) || "unknown" : null };
  }
  return { tasks: out };
}

export function queueCounts(state: QueueState): QueueCounts {
  const c: QueueCounts = { queued: 0, running: 0, retrying: 0, failed: 0, total: 0 };
  for (const t of Object.values(state.tasks)) {
    c[t.bucket] += 1;
    c.total += 1;
  }
  return c;
}

/** Busiest agent first, ties broken alphabetically. Capped at MAX_AGENT_CHIPS. */
export function agentChips(state: QueueState): AgentChip[] {
  const by = new Map<string, AgentChip>();
  for (const t of Object.values(state.tasks)) {
    const chip = by.get(t.agentId) ?? { agentId: t.agentId, queued: 0, running: 0, retrying: 0, failed: 0, total: 0 };
    chip[t.bucket] += 1;
    chip.total += 1;
    by.set(t.agentId, chip);
  }
  return [...by.values()]
    .sort((a, b) => (b.total !== a.total ? b.total - a.total : a.agentId.localeCompare(b.agentId)))
    .slice(0, MAX_AGENT_CHIPS);
}
```

```tsx
/*
  The live queue strip (P4). Autonomy made visible: what the swarm is chewing on
  right now, with no refresh and no polling.

  DATA FLOW (program plan §2 — push first):
   · mount / SSE resync          → GET /runtime/engine/runs   (authoritative)
   · task.queued|started|retried|failed → pure reducer (instant, optimistic)
   · any of the above + delivery.* → 400ms TRAILING debounce → authoritative re-read

  Why the re-read exists: the v1 event catalog is CLOSED and has no success-terminal
  name, so a task reaching DONE/HELD leaves the queue without announcing it. The
  debounce is trailing, so a burst of transitions costs exactly one request and it
  lands after the transitions settle. No timer runs while the bus is quiet.
*/

const RETRUTH_DEBOUNCE_MS = 400;

export interface QueueStripProps {
  /** Newest catalog event from the app-wide SSE subscription. */
  lastEvent: RuntimeEvent | null;
  /** Bumped on every successful (re)connect — forces an authoritative re-read. */
  resyncNonce: number;
}

export function QueueStrip({ lastEvent, resyncNonce }: QueueStripProps) {
  const [state, setState] = useState<QueueState>(EMPTY_QUEUE);
  const [maxInflight, setMaxInflight] = useState<number | null>(null);
  const [inflight, setInflight] = useState<number | null>(null);
  const [reachable, setReachable] = useState(true);
  const [retruth, setRetruth] = useState(0);
  const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  // ── authoritative read ────────────────────────────────────────────────────
  useEffect(() => {
    let live = true;
    fetchQueueRuns()
      .then((r) => {
        if (!live) return;
        setState(fromSnapshot(r.tasks ?? []));
        setMaxInflight(typeof r.maxInflight === "number" ? r.maxInflight : null);
        setInflight(typeof r.inflight === "number" ? r.inflight : null);
        setReachable(true);
      })
      .catch(() => { if (live) setReachable(false); });
    return () => { live = false; };

  useEffect(() => {

      setRetruth((n) => n + 1);

              {counts.failed > 0 && <span className="helm-chip" data-tone="red">{counts.failed} failed</span>}
            </>
          )}
          {maxInflight != null && (
            <span className="helm-chip" data-tone="muted" title="Shared concurrency budget across chat, run and the engine">
              {inflight ?? 0}/{maxInflight} slots
            </span>
          )}
        </div>
      </div>

      {chips.length > 0 && (
```
