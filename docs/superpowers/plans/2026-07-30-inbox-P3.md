# P3 — Inbox UI + notifications Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **COMMIT POLICY (program plan §4):** there is **NO `git commit`** in this plan. Every task ends with **Checkpoint:** `git add -A && git status` — review, leave staged. Anyone who commits has violated the program's hard rule.

**Goal:** Make `docs/mockups/helm-inbox-merged-mockup.html` the real, live, push-driven Inbox surface — Delivery list + filters, full-diff review pane with Approve / Request-changes / Reject, a typed-APPLY gate for high-risk, one SSE subscription for the whole app, and a native notification + dock badge on `delivery.created`.

**Architecture:** P2 already serves everything (`GET /inbox`, `GET /inbox/:id`, `POST /inbox/:id/{approve,reject,request-changes}`, `POST /runtime/events/ticket`, `GET /runtime/events`). P3 is a frontend build plus one 1-line additive server read (see Task 4b) so browser `EventSource` can actually use ADR-052 §3 replay. New code splits into: a typed HTTP client (`inboxClient.ts`), one SSE hook with pure, unit-testable internals (`useRuntimeEvents.ts`), an additive `data-skin="helm"` token layer (`theme/helm.css`), and presentational components under `src/components/inbox/`. The existing 2s `state.json` poll is untouched and stays as the fallback watcher.

**Tech Stack:** React 19 · Vite 5 · TS strict · Tailwind 3 · Framer Motion 11 · `node --test --experimental-strip-types` · Electron 33 · SSE (`EventSource`).

## Task 4b: make ADR-052 replay reachable from a browser (1 line + test)

**Why this exists:** P3's exit criterion is *"reconnect replays missed deliveries."* ADR-052 §3 implements replay off the `Last-Event-ID` **header**. Browser `EventSource` cannot set headers, and its native reconnect (the only thing that sends that header) is structurally dead here because the ticket is single-use — the retry gets 401 and the spec closes the stream. So the client must re-mint and open a *new* `EventSource`, which sends no header. Without this line, replay is unreachable from the product and the exit criterion cannot be met.

**Security note:** the value is a monotonic row sequence, not a secret. The route stays ticket + origin + host gated; nothing about the auth model changes. `subscribe()` already clamps the value (`events.mjs:117` — non-finite → 0, negative → 0) and caps the replay at `REPLAY_CAP`.

### Manual e2e script (replaces `e2e/inbox.spec.ts`)

```bash

H="-H x-runtime-token:$T -H Origin:http://127.0.0.1:3006"
```
