MissionAlpha · how it should work

One door. One boss. A team that talks.

You hand a Jira epic or story to one bot. A Manager reads the ticket and your code, splits the work, gives each piece to whoever can do it, hires when nobody can, and comes back to you once with a summary and a yes/no. That's the whole product.

Manager

The product. Reads the whole ticket, opens your code, writes the task list, picks who does what by skill, asks HR when nobody fits, reviews the result and reports to you once.

  • Only speaks to Ash above and the team below.
  • Asks you questions once, up front, not ten times later.
  • If a worker is stuck, the Manager resolves it or escalates — you never see the noise.

The journey, step by step

  1. Ticket comes inYou hand Ash a Jira epic or story. Existing app or brand new — same door.
  2. Manager reads everythingThe ticket, the comments, the acceptance list. Then your actual code, so it knows how the app is built.
  3. Manager asks onceIf something essential is missing, it asks you up front. One round, not a drip.
  4. Task list, by skillScreens to Pikachu, server to Charizard, database to Bulbasaur, tests to Squirtle. Nothing outside a worker's skill ever lands on that worker.
  5. Skill gap → HRNobody fits? Manager asks HR. HR makes one new agent with exactly those skills, it appears on the board, it joins the roster for next time.
  6. Team builds in a safe copyNever on the real code. Workers talk to each other for handoffs and blockers. Squirtle tests as they go.
  7. Manager reviewsRuns the tests, reads the change, writes you one summary: what's done, what isn't, any risk.
  8. You say yes onceYour only touch. Then a pull request opens on your repo and the Jira ticket moves to Done with a comment.

Five rules that never bend

  • One doorYou talk to Ash. Ash talks to the Manager. Nobody else ever pings you.
  • The Manager owns the workDecomposes, assigns, tracks, reports. Workers never report to Ash or to you.
  • Skills are lockedA worker holds only its domain skills, enforced by the system, not by a polite prompt.
  • Peers talkWorkers hand off and unblock each other directly. The Manager gets updates, not every message.
  • Nothing ships without youSafe copy, tests, review, then one yes. The pull request is the only way code reaches the real repo.
